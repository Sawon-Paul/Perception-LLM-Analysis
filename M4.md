# M4 — car simulator on the chain

Simulated cars driving real PVS traces and transacting against the deployed
contracts.

## Install

Copy `src/car/` into `C:\Sawon\LLM\`, then:

```cmd
cd C:\Sawon\LLM
pip install web3
```

The chain must be up and the contracts deployed:

```cmd
cd chain
docker compose -f besu/docker-compose.yml up -d
node besu/verify.js
```

Wait for `peers seen by node 1: 3 of 3` before going further. Checking too
early gives a false halt — that happened three times during development.

## Run

**Register the cars once.** Each gets its own key in `config/keys/` and its own
owner id, so the distinct-owner rule actually binds.

```cmd
cd C:\Sawon\LLM
python -m src.car.simulate --register --traces "PVS 1" "PVS 2" "PVS 3"
```

**Then drive them.**

```cmd
python -m src.car.simulate --traces "PVS 1" "PVS 2" "PVS 3" --max-per-car 25
```

Detections are interleaved by timestamp so cars act in the order they really
drove, rather than one car finishing its whole trace first. Confirmation
depends on cars arriving separately.

**Drive one fault all the way to Closed** — the M4 done-test:

```cmd
python -m src.car.simulate --traces "PVS 1" "PVS 2" "PVS 3" --max-per-car 25 --repair
```

Expect: `report` → more cars `confirm` → at k distinct owners the fault becomes
Confirmed → the repair team claims it → check-backs saying the damage is gone
close it.

## What to look for

Per-transaction latency and gas land in `results/car_transactions.csv`. With a
2 s block period, median latency should sit near 1 s: a transaction waits on
average half a block.

The run prints how many faults reached each state. Some transactions will be
refused, and that is the system working: a car whose owner already contributed
to a fault cannot confirm it again. Those appear as `rejected` rows with the
contract's reason.

## The collusion experiment

Give several cars one owner and watch the distinct-owner rule stop them:

```cmd
python -m src.car.simulate --register --traces "PVS 1" "PVS 4" "PVS 7" --same-owner "PVS 1" "PVS 4" "PVS 7"
```

All three share an owner id, so the second and third confirmations of any fault
revert. Nothing they do reaches k. That is the Sybil/collusion row in the
security table, measured rather than asserted.

Note it registers cars by index, so run this in a separate `config/keys/`
directory or re-register deliberately — a car's key is its identity and its
reputation.

## Tested here

The geometry and the decision rule, exhaustively:

- haversine accurate to 0.02 m at 15 m and 0.11 m at 100 m
- evidence hash 32 bytes, deterministic, distinct for distinct detections
- report-vs-confirm across eight cases: nothing active, same spot, 40 m away,
  wrong type, several candidates, unknown position, and both sides of the
  radius boundary

**Not tested here:** the actual transactions. There is no Docker in the
environment this was written in, so the chain calls have never run. Expect to
fix something small on the first attempt — most likely an ABI path or a
contract revert message. Send me the first error and it will be quick.
